================================================================================
A NOTE ON WHERE THE ERROR GOES
================================================================================

`create_image_ref` (`image_resource_loader.py:162-177`) catches `OperationNotAllowed`,
`ValueError` and four other types into a `warnings.warn` and returns `None`. So at the level
the HTML backend calls, a refusal is a warning and a successful SSRF is indistinguishable from
a successful image load. The rows above call `load_image_data` directly so the guard's own
exception text is visible; the evidence for the attack row is the listener log either way.
