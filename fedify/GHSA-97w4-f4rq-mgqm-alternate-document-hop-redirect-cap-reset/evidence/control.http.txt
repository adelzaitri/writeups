Two claims: a bound on the number of redirects the **remote document loaders** follow, to
mitigate **resource exhaustion during remote key and document resolution**; and a stop on
revisiting the same URL within a chain. The control below shows both working. The attack run
shows the loader taking a second kind of hop on which neither applies, on exactly the path
that sentence names — remote key resolution.

================================================================================
THE ONE CONFIGURATION CHANGE, STATED PLAINLY
================================================================================

`allowPrivateAddress: true` is set in every row, control and attack alike. It is needed only
because the lab is contained on 127.0.0.1, and it gates `validatePublicUrl`
(packages/vocab-runtime/src/docloader.ts:318-320) — nothing else. It has no relationship to
the redirect counter or the visited-URL set.

**It is not load-bearing, and the control is the proof:** the cap fires with the flag set. If
the flag disabled the bound, the control could not have thrown. In a real deployment the flag
stays at its default `false` and the destination is the attacker's own public host, so the
guard is not in the path at all.
