Capabilities files are `opa capabilities --current` at the pin (206 builtins) with an
`allow_net` key added by hand. `opa capabilities --current` does not emit that key and
there is no CLI flag for it, so hand-editing is the only way to express the restriction.

  caps-allow-listener.json   "allow_net": ["rl-opa-listener"]
  caps-allow-example.json    "allow_net": ["allowed.example.com"]
  caps-none.json             "allow_net": []

Two synthetic receivers. The UNIX socket is a bind-mounted file, so the unix:// rows run
with NO network namespace at all (`--network none`); the TCP rows use a bridge network
with a sidecar listener that publishes nothing to the host.

================================================================================
ROW P — POSITIVE CONTROL. allow_net names the destination, so the request arrives.
Without this row a reader cannot tell a working check from a broken harness.
================================================================================

$ docker run --rm --network rl-opa-net -v $LAB:/w:ro openpolicyagent/opa:1.21.0 \
    eval --capabilities /w/caps-allow-listener.json --strict-builtin-errors -f json \
