Both controls refuse. The attack row returns status_code=200 and the socket's marked body.
`ast.CapabilitiesForThisVersion()` never assigns AllowNet, so an embedder that does not set
it has no restriction at all; one that does set it has no restriction on this destination
kind. The behaviour is identical to the CLI because the enforcement point is the same
function, v1/topdown/http.go:409-423.

================================================================================
WHERE THE CHECK SHOULD HAVE BEEN
================================================================================

v1/topdown/http.go:629-632 — the destination is rewritten out of the `socket=` query
parameter and the result is never re-verified against the allowlist:

	var transport *http.Transport
	if ok, parsedURL, tr := useSocket(url); ok {
		transport = tr
		url = parsedURL

`allow_net` is consulted at exactly two points, both on the URL authority only:
  v1/topdown/http.go:475 — the caller-supplied "url" key
  v1/topdown/http.go:648 — the CheckRedirect hook

and `verifyURLHost` (v1/topdown/http.go:409-423) reads `parsedURL.Host`, which for a
`unix://` URL does not determine the destination at all.

`socket` has exactly one consumer in the whole tree — `useSocket` itself
(grep '"socket"\|socket=' over v1/topdown/ returns only http.go:366,367,389,390) — so there
is no second enforcement point and no normalisation of the path.

================================================================================
SCOPE AND CONFIGURATION, STATED PLAINLY
================================================================================

- Synthetic receivers only. The UNIX socket is a purpose-built Python listener that logs
  what it receives; no real container-runtime or agent socket was ever a destination.
- No non-default exposure. The unix:// rows ran with `--network none`; the TCP sidecar
  publishes nothing to the host (`.NetworkSettings.Ports` == {}).
- One request per row. The finding is that a request reached a destination the allowlist
  excluded; ROW A2 characterises the request shape and nothing further was extracted.
- The `allow_net` key was added to `opa capabilities --current` by hand because OPA emits
  no such key and offers no flag for it. That is the documented way to use the feature
  (docs/docs/operations.md:138-147), not a lab workaround.
